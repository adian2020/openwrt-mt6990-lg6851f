# 跨槽共享取证工具与报告

## 实机证据与问题

用户实际运行并发生回退的是v1.0.17（45e730b），没有安装v1.0.18。overlay自动报告是v1.0.18才加入的能力，不能因为v1.0.17没有报告而认定刷入异常。原固件5.4.238没有挂载/overlay，共享P46实际挂在/data；其设备源还可能使用别名，旧采集器按挂载源字符串匹配mmcblk0p46会漏掉它。

共享日志记录5次B槽6.18.44启动，均出现AP-ENABLED与modem5g接口up；3次有procd受控shutdown，末次记录到内核1462.95秒，没有已写入日志的panic/Oops/HANGDET confirmed。当前只读p39的文件系统则为原厂21.02.7、5.4.238。仍待原厂启动脚本和刷写/恢复记录定位原因，不把受控关闭认定为内核卡死，不认定原厂一定自动覆盖，不改厂商回退机制。

## 修改

后台归档不再接受任意名为/overlay的可写挂载。先核对P46分区号46、PARTNAME=user_data、5187456扇区，再按sysfs设备号在/proc/self/mountinfo寻找完整根目录、ext4、可写挂载。识别/mnt/mt6990-data、/overlay、/data及设备源别名，不因另一个overlay存在而写错分区；不自行挂载或修复文件系统。

P46内的固定相对位置：

```
lg6851f-ab-tools/collect-ab-failure.sh
lg6851f-ab-reports/boot-<本次启动UUID>.txt.gz
```

保存独立只读取证脚本，原子替换、权限0700，回退后可用原固件的sh运行；正常启动使用固件内脚本，不从共享目录自动执行代码，不给原固件安装启动钩子。报告目录0700、报告0600，维持最近8份、压缩上限4MiB、至少16MiB可用空间、同启动去重与校时保护。若旧/overlay本来就是完整P46挂载，则新旧报告位于同一物理目录，不搬动或清理其他证据。

采集器同样核对P46身份、按设备号识别已挂载的完整ext4分区，可读只读挂载。增加当前固件信息、pstore挂载状态、共享报告/工具列表、最新升级轨迹与明确标为历史的overlay固件ID。不把/data/.mt6990-firmware-id当作当前A/B根分区的版本证明。不主动挂载、不写misc、不清pstore、不读取clk_summary、不重启；报告仍写/tmp。

## 原固件回退后的用法

只有包含本次修改的固件已经启动到S99、确认P46可写并成功保存工具后，以下文件才会存在。在本机原固件P46挂在/data时：

```sh
ls -lt /data/lg6851f-ab-reports/
sh /data/lg6851f-ab-tools/collect-ab-failure.sh
cat /tmp/lg6851f-ab-failure.txt
```

挂载点不叫/data时需使用实际P46位置。共享脚本运行只读取源数据，写/tmp报告；不会自动把本次原固件报告写回P46。脚本不包含新版专用函数库依赖。

共享存放解决跨槽可访问性，不能保证捕获Linux入口之前、P46未可用或S99之前的故障。原固件也不会仅因共享区多了脚本就自动执行它。此类失败仍依赖ramoops、已有P46运行记录或串口；不能以报告缺失证明未失败。v1.0.17不会因源码修改而获得新功能。

## 验证与边界

10项真实shell夹具回归通过：压缩/权限/去重/8份轮转、时钟回退保留当前报告、错误overlay与只读/未挂载/局部bind/非ext4拒绝、真实P46 extroot兼容、分区身份拒绝、低空间及目录符号链接拒绝、同启动更新工具不重写报告、原厂别名与只读共享挂载读取且源数据不变、无挂载/错分区明确提示、源码与安装脚本一致。夹具不创建设备或挂载真实分区。

源码包13入口检查、升级状态8项、联网恢复5项、shell/Python语法及git diff检查通过；未做完整固件编译或原固件实机运行。没有触发云编译、恢复监控、修改签名/A-B打包、槽位优先级、计数、成功标志、启动保护、QoS、拨号或其他插件。
