# 启动阶段计时与PHY、热点观测

## 目标与边界

用户要求测量驱动加载、首次配置及PHY出现到热点启用各阶段。新增打点只测量，不调整启动顺序、驱动、监管域、EEPROM准备、蜂窝拨号等待、A/B控制或内核启动参数。本次不编译、不重启设备，不声称已经取得实机耗时。

当前正在等待用户贴回本次启动的只读日志，优先从现有内核、无线及bootprof记录分析。旧固件没有kmodloader和逐个uci-defaults起止打点时，不能事后复原这些阶段，也不能用开机后查询到的状态冒充首次出现时间。不要求恢复出厂或为了采集立即重启。

## 计时点

统一读取 `/proc/uptime`，起点为内核启动，不包含引导器耗时。与上电/按重启到手机发现WiFi的外部秒表口径分开。

- preinit已覆盖区间、mount_root完成；不是最早内核入口。
- S09厂商存储准备，每个实际挂载动作及WiFi EEPROM准备。
- S10boot的无线配置生成、kmodloader起止、uci-defaults总区间；逐个待执行默认脚本的起止和返回码，以及commit、sync、reload_config阶段。
- WiFi首次助手等待PHY、配置生成和wifi up请求起止；返回仅说明请求结束，不当作热点已经启用。
- ieee80211 add hotplug处理时间和seqnum；该时间可能受事件队列影响，不冒称wiphy_register精确时刻。

`lg6851f_bootmark` 在tmpfs追加一行阶段数据，首次写入启动UUID，并以debug优先级写入已有内核消息通道供P46有界日志保留；不执行AT、ubus、debugfs、主动挂载或sync。它不改变业务调用的成功/失败返回，忽略不可写的日志位置和符号链接。

## PHY和热点后台观察

S08的procd一次性服务在S09/S10之前异步启动，不阻塞这些启动项。它每轮观察 `/sys/class/ieee80211/phy*`，最多约每秒执行一次带1秒超时的 `hostapd status`，不查询模组、不发起wifi up/down或网络reload。

PHY首次目录观测记录在 `phy-observed`，上轮扫描起点作为辅助下界。首个hostapd接口 `running=true` 后记录 `ap-running-observed` 和第一次状态快照，然后退出；使用上次成功查询的请求开始时间作为未运行下界，使用本次查询返回后的内核时间作为已运行上界。失败查询不产生虚假的否定边界。

通常采样间隔约1秒，但驱动阻塞、CPU调度、ubus超时可能扩大观测区间，不能保证正负1秒。采样不等于精确的内核PHY注册或AP-ENABLED事件；原始hostapd日志仍保留作对照。首个热点可能是2.4GHz或5GHz，状态快照可用于核对；不能把首个AP总值硬套给每个PHY。

观察器使用约180秒绝对uptime预算，包含RPC等待。没有热点、用户关闭无线或热点长期初始化时，超时后退出，不启用无线、不自动重试服务。观察有少量CPU和日志开销，未用实机量化。

## 采集和分析

新固件正常启动后，在SSH读取：

```sh
cat /tmp/lg6851f-boot-stages.log
cat /tmp/lg6851f-boot-first-ap.json
```

也可下载运行仓库的 `scripts/lg6851f-collect-boot-dashboard.sh`。采集器版本4把当前阶段文件、当前和P46原始日志、bootprof及首次AP快照汇总至 `/tmp/lg6851f-boot-dashboard.txt`，不调用看板或模组采集接口。报告可能含无线MAC、命令行及设备身份，分享前可脱敏，但保留时间戳、阶段名和返回码。

将报告复制到电脑后执行：

```sh
python3 scripts/lg6851f-analyze-boot.py lg6851f-boot-dashboard.txt
```

分析器只使用报告中的本次启动阶段区段，不把P46旧启动混进当前区间；原始阶段输入中有多个启动UUID则拒绝。缺少起止点不计算；按耗时列出本次实际执行的uci-defaults脚本，失败的脚本仍保留供下次重试。

kmodloader时间包含整个模块批量加载，不等于单个mt76或固件请求耗时。驱动内部细分以原有内核initcall/mt76/mt7990/firmware日志支持为限，本轮不启用额外内核调试参数或读取clk_summary。反复重启时，成功的首次配置脚本已删除，测到的是本次残留项，不能冒称重新测过首刷。

## 验证

新增7项本地回归执行实际shell辅助器和S10boot，使用隔离路径和模拟命令验证：单调时钟/启动UUID/私有权限、日志失败不影响业务、符号链接不写入、默认脚本失败保留、kmodloader失败仍按原流程继续、最终reload退出码保持、PHY及running观测、用户关闭无线时有界退出、不以wifi up返回伪称热点启用、旧启动隔离。

原有WiFi首次启动6项、拨号恢复5项及源码包13入口检查通过；shell/Python语法、workflow YAML和diff检查通过。没有实机驱动加载压力测试、首次配置耗时或上电到热点时间结果，没有完整固件编译。

另一工作树暂停的早期打点草稿只读取并核对了计时差异，在当前干净源码中补齐、验证；未覆盖另一工作树，未合入软件库草稿或其他驱动优化。
