# 正常启动确认与单槽TRY清零修复

## 问题和最终行为

本机preloader的特定复位路径会递增当前优先槽TRY，而原厂正常启动在S99清当前TRY。自编译缺少这一确认步骤，正常启动/重启也可能留下累计值。前轮已用实际前级函数验证阈值与先检查、后递增的顺序；此轮补齐正常启动确认，不改变失败回退机制。

确认完成后，只写当前槽TRY一个字节：A为misc偏移2061，B为2066。优先级、SUCCESS、UP、另一槽TRY及其余记录不变。不复制分区、不改硬件启动区、不调整阈值、不禁用watchdog/HANGDET/panic，不改签名或A/B打包。

## 什么情况下才确认

新增S99 procd一次性后台服务lg6851f-boot-confirm，执行/usr/sbin/lg6851f-confirm-boot，无respawn，不阻塞启动队列，不反复写计数。

- 只接受本机固定LG6851F分区布局、6.18系列内核、ROM中的40位固件身份及合法BCAB v1双槽。实际bootslot与root分区必须一致，当前槽必须仍有较高优先级。
- PID1进入STATE_RUNNING后，以0600权限独占创建/tmp/lg6851f-init-complete，内容为本次boot UUID和启动时钟。STATE_SHUTDOWN删除凭据。其他目标编译成空操作，调用保留errno，不修改状态顺序/退避/watchdog；该凭据独立于测量日志，日志不存在不影响创建。
- 后台至少等到开机120秒；network、rpcd、uhttpd处于running且PID集合连续稳定30秒，netifd的network.interface dump实际响应。服务PID变化或检查失败会重新计算稳定窗口，最多观察600秒。
- 不依赖SIM、WAN注册、运营商信号、公网、物理链路或无线客户端；不发AT、不调用模组、不启停网络。
- rcS/原厂启动服务/升级正在运行、升级标记存在、凭据不可信或不属于本次启动、槽位记录变化时拒绝。

这是本机启动完成和核心服务可用的判定，不是全面硬件或内核压力自检。启动没有完成时不清计数；保护机制仍由原厂前级执行。

## 写入与持久证据

工作进程有独立原子目录锁；实际确认与手动切槽、升级共享/tmp/lg6851f-bootctrl.lock。只在观察结束后短暂持有启动控制锁，不让观察窗口阻塞用户操作。启动时取得的原始32字节快照，在加锁、取证前后都须保持不变；手动选择和升级结果不会被覆盖。

按分区号、PARTNAME、大小、设备号和完整可写ext4挂载识别共享P46，不自动挂载。至少保留1MiB可用空间。先保存32字节before.bin和带固件/UUID/槽位/原始值/预期值的status.json，sync后再次核对健康状态、快照与当前槽，才尝试单字节清零并sync，对整个32字节读回。

证据目录：

```
共享P46/lg6851f-boot-confirm/boot-<本次UUID>/
  before.bin
  status.json
```

新系统常见为/overlay/lg6851f-boot-confirm，原厂挂/data时为/data/lg6851f-boot-confirm；按实际P46挂载位置为准。目录0700、文件0600，保留最近8份，当前份不因时间回退而被轮转删除。状态包括prepared、confirmed、refused、write-failed、readback-failed；prepared不等于已确认成功。

本次启动一旦进入写入尝试即留下/tmp/lg6851f-boot-confirm.attempted；重启服务不会再次清零，失败也不自动反复写。读回发生不明变化时保留证据，不用整条旧记录回滚覆盖他人改动。若TRY已经为0，只记录正常启动，不实际写misc。

只读取证采集器版本4同时展示共享确认记录，独立下载版与安装版一致；原有pstore、运行日志和最近8份压缩报告保留。

## 验证与限制

宿主普通文件夹具执行真实shell，不创建或访问块设备；虚拟启动时钟替代等待，root身份/设备类型映射为夹具，其余备份、单字节dd和读回真实执行。覆盖A/B只改对应字节、已为0不写、同次启动不重写、初始化未完成/开机太早/服务失败不清、PID重启重算窗口、错误凭据/身份/布局/实际槽/优先级拒绝、升级及锁/共享区拒绝、备份竞态、取证时核心服务变化、写失败与外部改动不回滚、权限及8份轮转。

真实C头文件本地编译测试验证PID1凭据生成/删除、权限、UUID、errno、非PID1/其他目标空操作及符号链接拒绝；固定procd源码补丁零fuzz应用，原有ubus退避、注册顺序测试保留。

额外联动用户上传的原始preloader函数与真实shell夹具：旧TRY=3的本轮检查继续B，随后递增到4；正常完成启动后真实确认脚本清为0，下一轮不回退。初始化未完成时脚本不清4，下一轮原始前级仍请求切A。两例仅为离线模拟，存储、PMIC、硬件启动区和复位均为夹具，不是真机试切槽。

没有在本地完成整个目标固件构建，未操作实机、刷写、重启或自动清用户当前设备计数。用户目前原厂5.4不会应用此服务；需要后续明确授权云编译，验证新固件打包并刷入后再验收。
