# 手动选槽与引导器取证

## 已确认和待确认的机制

用户在原厂B槽5.4系统环境下，用电脑工具明确写boot_b和rootfs_b；v1.0.17随后5次在B槽6.18.44中运行并联网。取证时A原厂已启动，B也已成为原厂内容；这两个时间点不矛盾。

本机上传的原厂bootctrl.sh定义：misc为BCAB记录，基址2048；A优先级/重试/成功/升级字段在2060/2061/2062/2063，B在2065/2066/2067/2068。脚本MAX_RETRY=03；原厂zmtk_boot_done在S99正常开机时清当前槽TRY；另一槽TRY>3时调用ab_image_sync，复制相反槽的16个分区到目标槽，包括boot、rootfs及preloader等。该部分已用上传源码的实际函数做隔离回放确认。

引导器选择另一槽启动，与原厂Linux启动后把另一槽恢复成当前槽镜像，是两段不同机制。不能仅凭Linux恢复脚本的>3条件断言LK的所有切槽条件。TRY不是内核错误码；panic、硬复位、断电、签名/载入错误是否分别走同一个递增路径，递增发生在选槽前还是验签后，仍需本机LK/串口证据。

原始运行日志中，受控shutdown之后的下一次启动也出现boot.reason=4，不能单独把该数字当作某个内核错误的证明。当前自编译代码未见原厂对应的正常启动清当前TRY路径，支持“正常开机未清零导致累计，随后回退及原厂恢复”的解释。但已有dmesg从1585秒之后才保留，缺少实际恢复发生时的QL_AB记录；不声称已完整实机复现。此轮不自动补写启动成功或后台定时清计数。

## 手动功能

入口：系统 → 启动槽位。

- 当前槽由cmdline bootslot与root分区交叉核对；下次偏好由优先级比较单独显示，不把优先级当成实际运行槽。
- 只支持已核实的LG6851F eMMC布局、BCAB v1双槽及已知字段范围。核对misc/boot/rootfs的PARTNAME、扇区数，读取目标Android boot/SquashFS头。
- 镜像头通过不能证明签名有效、boot与rootfs来自同一构建，也不保证目标可启动。签名和启动是否成功仍由原有引导链判断。
- 页面要求用户确认必要备份及原厂可能覆盖另一槽的风险，并输入目标字母；提供仅设置、设置并重启两个明确动作。只读账户不显示可用写入按钮，写RPC与system.reboot分离授权。
- 目标success不为1或另一槽TRY>3时，按原厂可能恢复另一槽处理，默认拒绝CLI写入；页面明确展示风险并在用户确认后传递接受标记。不会为躲避原厂恢复而偷改另一槽计数或成功字段。
- 设置改变的是默认优先级，不承诺只生效一次或一定启动成功；失败自动回退保留。

独立工具：/usr/sbin/lg6851f-slotctl。正常新固件后台归档也会把它保存为共享P46的lg6851f-ab-tools/slotctl.sh；原固件P46挂/data时可用sh手动运行。旧v1.0.17不会自动拥有新工具或页面。

```sh
# 只读，返回JSON和当前control快照
/usr/sbin/lg6851f-slotctl show

# 用户明确决定写入时，用上一步完整64位十六进制control替换占位符
/usr/sbin/lg6851f-slotctl select b --expect '<control>' --confirm

# 仅在已备份两槽镜像并接受原厂可能覆盖另一槽时增加此参数
# --allow-vendor-recovery
```

工具本身不重启，不下载或复制固件。它只写A/B优先级和目标TRY共3个字节，保留SUCCESS、UP及另一槽TRY、其余控制记录。先在核实的共享可写P46保存32字节控制记录、完整512KiB misc及JSON说明，路径lg6851f-slot-backups/bootctrl.*，目录0700、文件0600。备份失败、状态快照变化、错误布局、镜像头无效、共享区不可写均拒绝操作。

手动工具与本固件platform_do_upgrade共享/tmp/lg6851f-bootctrl.lock原子目录锁，拒绝并发写控制。stage2会把原/tmp移动到RAMFS中的/tmp，锁不会因/var目录重建而失去互斥。每一步写入后对整个32字节读回；失败时仅当记录仍符合本次已知中间状态才恢复本次3个字节并核对。检测外部不明改动时不盲目覆盖，保留备份并提示不要重启。SIGTERM/INT/HUP在写入阶段尝试同样受限恢复。断电/SIGKILL不能保证软件回滚完成；异常遗留锁不自动删除，应核查后处理。

原厂服务和旧版升级程序不遵守这个新锁，工具会拒绝检测到原厂rcS/zmtk_boot_done或sysupgrade/stage2正在执行的情况。不要在开机初始化或其他刷机操作期间运行。新增互斥不改变固件签名、CONTROL、A/B打包或原有升级写入顺序。

切回已经被原厂恢复的B槽，只会启动B目前已有的系统；不会自动找回以前的6.18镜像。

## LK只读采集

scripts/lg6851f-probe-bootloader.sh只按sysfs名称选择lk_a/lk_b，核对块设备和大小，单分区上限8MiB、单次读取超时12秒。输出到/tmp的独立目录及tar.gz，包含LK镜像、SHA256、现有控制字节和内核日志；不读整盘、不读NV、不写misc、不自动挂载、不切槽、不重启。找不到LK或大小超限则明确退出，不能跳过身份检查。

收到LK后需要定位TRY读写、阈值比较、验签/加载/复位原因分支，才能明确“哪些错误导致何种计数与切槽”。公开通用AOSP/其他平台代码及本仓库注释不替代本机实现。目前这一步尚待用户提供LK采集产物。
