# 云编译测试兼容修复及参考插件核对

## 运行 42320309211 的失败原因

源码提交 7ffed269b980f55e534b4d9318260848771c5ea8 已完成 make、A/B 签名包生成、
最终根文件系统检查和 21 项数据/API 测试。随后 7 项 QoS 离线测试在解析输出时
全部报 JSONDecodeError，工作流停止且未发布这些产物；这不是短信编译报错。

取回完整失败日志和诊断产物后，使用仓库指定的
ucode-2026.06.03~3ec4e5c2 源码重建本机解释器，源码归档 SHA256 与配方一致：
bc0ccef8b34defd524705c73982b39ba9e86fab588e531eba1915eecc57a8351。
原测试可稳定复现：模拟 ubus 模块用了较新解释器才支持的 throw 语句，
固定版本返回 255 和语法错误，旧测试只检查 254，又未打印 stderr，导致真正原因
被空字符串的 JSON 解析错误掩盖。

将三处模拟接口断言改为现有解释器支持的 die()，仍拒绝非只读命令、错误 CID
和不正确的二进制请求。新增空输出断言，直接展示退出码及 stderr，不跳过测试。
固定版本下 7 项 QoS 及 13 项短信转发测试通过；未恢复实机 QCI/5QI 采集。

构建脚本先构建同一仓库版本的 ucode/host 并运行既有数据、QoS 模拟和短信测试，
通过后继续原有完整 make、签名和 A/B 打包。最终根文件系统检查仍在 make 后执行。

## 用户补充仓库中的两个插件

只读核对来源：
https://github.com/adian2020/LG6851F-Pro/tree/0e1518ed632388e814032e0831560d22d9488981/package/vendor

- luci-app-5gmodem：短信列表仍用 CMGF=1、CSCS=UCS2、CMGL="ALL"，
  发送走既有 modem5g-sms-send，原页面只开放 ASCII 发送；该目录没有自动短信
  转发后台。无需用旧的页面或射频开关实现覆盖当前修复。
- luci-app-fiberhomedash：有 MT6990 温度、网络、缓存采样与载波展示代码，
  以及 QNWCFG AMBR、中心频率、Point A 和 CGCONTRDP 等接口线索。
  其中 QCI 代码按固定 CID 顺序尝试、取 CSV 第 19 项，不能据此确认已匹配当前
  上网 APN 或正确解释 QCI/5QI 字段；带宽推算和字段位置也须实机验证。
- 参考包 Makefile 引用的 files/usr/share/luci/menu.d/luci-app-fiberhome.json、
  files/usr/share/rpcd/acl.d/luci-app-fiberhome.json、files/etc/init.d/fiberhomedash
  在该提交目录树中不存在，不能不补齐就原样打包安装。

本次仅记录可用线索，不移入另一套周期 AT 采集器，不恢复已暂停的 QCI/5QI 排查，
保留现有 Aurora 看板、短信三渠道、射频与升级迁移流程。
