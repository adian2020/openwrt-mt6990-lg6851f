# 旧版 QoS 临时热测试

用户明确选择临时恢复“默认关闭之前的旧版QoS实现”进行对照，不刷机、不启动云编译。本工具只放在源码scripts目录，未改目标固件的正式QoS文件或默认配置，也未恢复任何内核/驱动补丁。

## 恢复内容

旧程序固定为78a0547bc38311f6cfb48d707c1203534d1d5ea7，文件SHA256为3f8c535dbc2a28909955181232c3c06041959b5b7e69718660856e937a8c5496；已经与远端该提交内容逐字节核对。下载后原样执行，不改其中CAKE、IFB、autorate-ingress、diffserv4、NAT、主机隔离、ACK过滤、overhead和种子带宽参数。

新旧启用时的核心CAKE参数相同，这次主要对照旧版的配置/清理逻辑及30秒成功、3秒失败的调用节奏。外围控制器仍核对板型、6.18内核、现有正式程序/服务/接口事件脚本指纹、当前关闭配置、启动UUID和无升级操作；发现其他TC归属或正式控制器接管时停止，不无条件覆盖其规则。因此这是受控临时对照，不是永久退回整版历史固件。

旧版启用后曾在高速下载时发生内核卡死，这次不宣称已经修复该问题，应先短时间观察。测试期间不用网页QoS按钮；该按钮仍显示正式配置的关闭状态，不代表临时旧版没有安装队列，必须看脚本status的实际tc输出。

## 临时配置和回退

- 正式QoS保持enabled=0；先在页面关闭，且不能有未保存配置。
- 旧程序及配置放在/tmp/lg6851f-qos-legacy-test。利用原生UCI_CONFIG_DIR加载私有配置，只在该目录启用旧程序，不对/etc/config执行set或commit。
- 备份保存在/root/lg6851f-qos-before-test.XXXXXX，程序、服务、接口事件和配置分目录保存，避免同名文件覆盖。
- 先停止正式控制器，再启动只存在于/tmp的独立procd服务。无开机链接、无自动respawn，网络重配失败按旧节奏重试，但外部冲突或显式停止不恢复。
- off先撤销测试意图并停止周期任务，在同一TC锁下检查归属、清理旧规则，读回IFB已移除；不恢复已被其他组件接管的队列。
- restore执行off后恢复此前正式控制器的停止标记状态，删除临时目录；正式持久配置仍关闭。重启也会清除临时任务和规则；备份保留，不自动重启。

## 使用

先从聊天中给出的固定提交下载scripts/lg6851f-qos-legacy-test.sh并核对SHA256。以下动作由用户在本机SSH明确执行：

```sh
# 开启旧版对照；下载旧程序可使用之前用过的代理
sh /tmp/lg6851f-qos-legacy-test.sh on https://v6.gh-proxy.org/

# 查看实际WAN/IFB队列和重定向
sh /tmp/lg6851f-qos-legacy-test.sh status

# 关闭旧版并停止周期配置，再做关闭状态对照
sh /tmp/lg6851f-qos-legacy-test.sh off

# 再次开启旧版
sh /tmp/lg6851f-qos-legacy-test.sh on

# 完全退出临时测试
sh /tmp/lg6851f-qos-legacy-test.sh restore
```

备份路径由on输出，日志位于/tmp/lg6851f-qos-legacy-test/test.log。失败或冲突时保留输出和日志，不删除未知网络规则。只比较同一测速节点、相近时间和相同无线连接下的结果；测试结果仍需用户提供。
