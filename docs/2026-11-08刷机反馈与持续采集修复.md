# 刷机反馈与持续采集修复

源码仅 cloud-build。用户授权在所有反馈修复并检查后启动云编译及监控，构建失败自动查错修复重编。不会操作实机或恢复另一个LG6851F-Pro项目。

## 实机反馈与原因

- 首刷约80秒才有WiFi，蜂窝制式unknown且十分钟无网、信号灯不亮，重启后恢复。源码发现状态进程在首次拨号前争用CMIPC6，恢复程序又直接跳过未up接口。现状态CMIPC查询让行首次拨号，初始状态采集提前到10秒；失败身份读取按60秒重试，避免一次失败后等一小时。自动拨号开启、射频未被用户关闭且接口不在pending时，连续三轮down请求netifd重试，不自动重置射频。用户关闭自动拨号或射频时不干预。此为已确认代码缺口修复，首次失败的完整实机原因和启动总耗时仍需日志验收。
- 看板WiFi、客户端、DHCP及存储在浏览器返回后变未获取。原采集分system/network/wireless/complete发布，中间帧缺失数据组；新采集携带同次启动的成功快照，仅在对应新数据成功后更新该组。查询失败保留旧值，成功返回空列表仍表示真实无客户端。移除尾部日志作为启动耗时证据的错误用法。
- 小区依赖先打开“状态与小区”，无线参数几分钟后清空。增加独立后台串行采集：联网初期读取ECELL和当前CID的QoS，稳定后复用已验证sample_nw 7/21/25子项5/33会话，每120秒更新高级参数。页面只读缓存，慢采集不进入看板RPC；读取失败保留成功结果与时效说明，不订阅BLER，不新增AT端口所有者。与手动读取共用任务锁，在模组控制/恢复期间让行。
- 频点633984、640000处于n77/n78重叠范围，不能凭频点猜频段。优先匹配厂商实际载波读回的同制式、同频点、唯一频段，确认n78时各页面显示n78；缺少证据时仍保留候选说明，不强制把全部重叠频点写成n78。新看板、状态页和共享模块使用新资源路径，减少旧缓存影响。

## 界面调整

- QCI行按用户指定保留标签，取当前上网CID的AT+C5GQOSRDP读回值，不写死8；内核保存kind为5QI。CID必须来自当前modem5g接口，拒绝把IMS承载或无返回当成0，不换算未确认AMBR单位。
- MCS行改为载波聚合，显示各实际载波的频段和频点，如n78 633984；带宽上下行相同时简化为100 MHz。调制继续显示已取得原始编码，未确认QAM映射不推测。
- 温度仅保留SoC、CPU、主板、调制解调器，金黄色深底标签。SoC使用soc_max，CPU和调制解调器各取对应传感器最大值；主板仅使用明确board/pcb/mainboard传感器，不把芯片infra或SoC复制成主板数值。无对应传感器显示未获取，后续可核对厂商传感器位置。
- 删除电源和USB网络；CPU、内存、存储保持三卡布局。
- SSID只显示名称并去重；信道优先选择真实5GHz接口，显示信道、频段和EHT模式/带宽；加密显示原名，隐藏SSID显示是/否，国家小写代码。
- 无线和DHCP设备名称过滤星号，结合租约、luci-rpc HostHints、静态DHCP和已知同MAC名称；没有真实名称时使用地址/MAC，不能保证未上报名字的Android设备自动显示pixel7PRO。协商链路速率以Mbps显示，AP接收对应客户端上传，AP发送对应客户端下载，不冒充实时吞吐。
- 只保留路由器重启，去掉关机选择。
- “重启调制解调器”接入已验证射频API的无线协议栈重启：恢复互斥保护、停止数据接口、射频off/on及读回、释放控制锁后请求拨号；不重启路由器，不关闭WiFi，不修改保存的用户射频策略。失败时尝试恢复原应开启状态并提供状态/日志，不能称为整个基带硬件复位。
- 本机号码继续使用标准只读AT+CNUM，修正返回逗号后有空格时的解析；未取得号码时不能从IMSI/ICCID推导。用户已补充实机输出，见下方核对记录，不主动执行实机命令。

## 补充实机核对

- 当前接口up=true、pending=false、autostart=true，射频radio_enabled=1、自动拨号auto=1，实际使用CID 2和ctnet，已获得IPv4地址及默认路由；接口连续在线8098秒。该状态表明当前数据接口已建立，不代替上网连通性测试，也不能证明首刷时正常。
- AT+CNUM仅返回OK，没有+CNUM号码行。此次没有可供解析的手机号，空格解析修复无法凭空得到号码；不能据此断言是SIM未写入还是模组固件未提供，暂保持未获取，不从IMSI/ICCID推算或伪造。
- 提供的当前日志未匹配到所查启动与恢复错误。缺少首次无网时的完整启动日志，首次失败根因仍未实机确认，不将重启后正常误记为问题已验证解决。
- 云编译42424815168仍跟进源码a462202，本次仅补充说明，不取消正在运行的编译或重复触发构建。
