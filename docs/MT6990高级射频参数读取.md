已根据用户提供的 mt6990-radio-details.txt 核对 sample_nw 的只读会话：
0 初始化、21 频段信息、25 的子项 5 完整载波信息、33 EN-DC 状态、

## 已确认字段与转换

| 来源 | 展示内容 | 规则 |
|---|---|---|
| nr_band / lte_band | 实际报告频段 | 0 表示本次没有有效频段记录，不显示为 B0/n0 |
| nr/lte_dl/ul_bandwidth | 下行/上行带宽 | 本次明确返回 100M，按物理带宽显示为 100 MHz |
| pcc/scc_type、band、pci、arfcn | 主/辅载波记录 | 每遇到一条 type 新建记录；重复 SCC 不继承上一条字段 |
| pcc/scc_dl/ul_mcs | MCS 下/上 | 本次为 1/28；0 是合法编码，不能按缺失处理 |
| net_ambr_dl/ul | 默认网络 AMBR | Kbps 按十进制乘 1000 得到 bit/s，再除 1000000 展示 Mbit/s |
| ims_ambr_dl/ul | IMS AMBR | 与默认网络承载分开保存和展示 |
| nr/lte_cqi | CQI | 信道质量指标，不是 QoS 的 QCI；QCI 继续未获取 |
| endc_available / dcnr_restricted | EN-DC 可用/限制标志 | 本次均为 0；展示状态，不伪装成用户设置开关 |

本次原始网络 AMBR 下行为 512000 Kbps、上行为 102400 Kbps，对应
512 / 102.4 Mbit/s。IMS 的上下行均为 512000 Kbps，不能用 IMS 上行
替换默认网络上行，也不能把网络 AMBR 当作下载测速或运营商限速承诺。

本次仅报告一条 NR PCC（n78），未出现 SCC。载波记录数是这次返回结果，
不能将四个邻区当成四载波，也不能据此断言设备永远不支持 CA。
只有 NR PCC、LTE 频段为 0、EN-DC 标志为 0 仍不作为当前 SA/NSA 的最终判据。

  核对第 7 项 getter 明确区分 NR5G/NSA5G，已加入主动读取，仍待新增实机读回。
  QCI、PPE 硬件会话数量及基带版本仍待独立接口证据。

## 固件接入方式

- /usr/bin/lg6851f-modem-details 仅允许固定读取会话，检查本机板型，并复用
  /var/lock/luci-modem5g-control.lock；通道忙立即返回，不争抢或自动重试。
- 查询加入已核对的第 7 项当前数据注册 getter；成功、3GPP 域且注册有效时，
  根据厂商明确的 NR5G/NSA5G 标签判别 SA/NSA，不将首选模式或十六进制位图套入。
- 厂商程序限制 45 秒，退出后持锁等待 6 秒；不停止 netifd、不执行 ifdown，
  不增加开机调用或周期厂商查询。该脚本的设备端部署尚未实机验收。
- luci.modem5g.get_radio_details 由“读取高级参数”按钮主动调用；启动未稳定时
  拒绝读取。只有会话完整、三组读取成功后才发布仅 root 可读的原子缓存。
- 状态看板自动轮询只读缓存，显示采样年龄，超过 180 秒标记过期；重启后不复用
  旧 boot_id 的记录。失败或通道忙保留上次成功缓存，不混合不同时间的部分结果。
- 增加原生 ucode 解析、错误/缺失单位、重复 SCC、MCS=0、AMBR 上下行、缓存发布、
  只读菜单序列、互斥及退出冷却测试，并检查 390px/1280px 浏览器布局。
- 测试采用合成位置标识，不提交用户的完整原始日志或小区标识。云编译仍暂停。
