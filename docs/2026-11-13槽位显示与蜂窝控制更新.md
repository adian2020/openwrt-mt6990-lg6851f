# 槽位显示、蜂窝控制与插件更新

本轮按用户要求仅修改、检查并推送源码；不启动云编译、不恢复自动监控。提交说明改为英文，界面和发布说明继续使用中文。Linux内核保持本机适配的6.18.44；本轮“OpenClash和内核”按OpenClash及Mihomo/Meta核心处理。

## A/B回退与取证

已有脚本是日志采集工具，不是切槽工具，也不会取消原厂失败回退。pstore保存内核崩溃后仍可能保留的ramoops记录，共享P46上的MT6990_CRASH_LOGS和MT6990_RUNTIME_LOGS保存已归档的崩溃和运行日志。此次把脚本加入固件/usr/bin/lg6851f-collect-ab-failure，并增加启动控制区域的只读原始快照，便于与前后两次启动比较；不写入misc/槽位、启动成功标记或重试次数。

自动回退发生在引导器选择启动槽位时，并不是Linux启动后执行的一条shell命令。仓库能找到的是lib/upgrade/platform.sh中升级完成后的槽位优先级与重试字段写入，以及按A/B分别签名的boot/rootfs打包。它们不是失败回退触发命令，本轮不改动这些代码，也不把其中的dd写操作当作用户诊断命令。尚未取得厂商引导器源码或某次失败的串口记录，不能声称知道完整重试阈值和每个状态字段的含义。

刷机前已知的一次高速下载panic与QoS路径有关，但没有足够证据证明所有A/B回退都由同一问题造成。要查明某次回退，需失败后尽早保留pstore、共享P46崩溃目录及完整串口启动日志；仅查看当前成功启动的logread或空pstore，不能排除前一次失败。

新固件回退后可运行：

```sh
/usr/bin/lg6851f-collect-ab-failure
cat /tmp/lg6851f-ab-failure.txt
```

v1.0.16的取证脚本当时只在源码scripts目录，不是系统命令。需要先下载固定源码版本的脚本再执行；若回到原系统不含wget/所需工具，应通过该系统已有的文件传输方式保存脚本和日志，不额外重启覆盖证据。此脚本只写临时报告，不主动挂载P46；原系统没有挂载共享分区时，报告会缺该部分日志。

看板温度行右侧增加“当前槽位：A槽/B槽”，优先核对/proc/cmdline实际root分区（p26=A，p39=B）与slot_suffix；发生冲突或无来源时显示未获取，不根据升级目标猜当前槽位。

## 网络模式与QoS

修复网络模式没有高亮的问题。读到SDK模式与NR限制时显示配置模式，否则仅以当前驻网类型作临时高亮，按钮title及页面说明区分两者。自动模式驻留SA不意味着已锁定SA。

原厂sample_nw菜单17/18以及getter55/54已静态核对：LTE=3，NR=15，LTE+NR=19，WCDMA+LTE+NR=21；NR限制分别含禁用SA、禁用NSA、两者禁用和两者均允许。SDK库set_nwmode会拒绝AUTO=21，因此使用仓库原有MIPC nw_set_rat设置模式，再用SDK独立NR限制接口区分NSA，最后读回两项。

- 自动：21，SA/NSA均允许。
- 仅4G：3，禁用NR SA/NSA。
- 5G SA：15，禁用NSA。
- 5G NSA：19，禁用SA。

沿用原控制/恢复锁和异步任务：先读取原设置，暂停原已连接数据接口，执行设置并确认读回；失败尝试恢复原设置，不把命令退出0当成功。恢复拨号前释放控制锁，避免与netifd互锁。不修改频段/小区锁状态文件。此路径有隔离测试，仍待实机验收。

按要求移除EN-DC按钮和开机应用占位。数据漫游接入现有network.modem5g.dataroaming字段，保存后请求netifd重载，不强行覆盖用户射频/auto选择；它是数据漫游允许策略，不是当前漫游状态。

网络模式区域右侧加入蜂窝QoS开关，默认关闭，手动开启须确认已知高速下载卡死风险。调用现有服务restart/stop，失败启用时退回关闭并尝试清理；保留安全迁移版本。此次没有以关掉hang detector、Panic或watchdog的方式处理问题。

## 每次构建更新插件

新增scripts/mt6990-update-plugins.py。每轮云构建在更新feeds后、配置生成前解析最新稳定上游版本并记录实际提交；源来自配置清单，下载失败、SHA256错误或本机适配合并冲突会停止，不静默使用旧包。普通feeds仍由feeds update -a更新，本机自有蜂窝/PWM/存储等代码以当前cloud-build源码为准。

本次已更新OpenClash 0.48.002、Mihomo 1.19.34、UU插件2.5。Aurora主题1.4.0和配置插件1.2.5已是当前稳定版，保留本机配色/模板兼容修改；定时重启跟进上游界面与翻译，保留本机安全cron后端及默认关闭配置。OpenClash启动联网保护、独立Mihomo存储包装器、UU原生ARM64编译和firewall4依赖均保留，UU仍默认关闭。UU客户端仍由插件根据NetEase官方API下载和校验，不预先启动加速服务。

OpenClash和Aurora文件通过上游基线/本机修改/最新上游三方合并，冲突即报出具体文件。UU的本机Makefile不被通用架构依赖覆盖，只补充上游新增依赖。Mihomo ARM64稳定版必须与GitHub官方资产SHA256相符，再更新下载配方哈希。

实际版本及上游提交写入固件/etc/mt6990-plugin-versions.json，云构建也会把PLUGIN_VERSIONS.json放入A/B发布ZIP中的签名目录。设备APK源、签名公钥、A/B刷写流程及自动失败回退保持原样，软件库扩充和启动驱动排查仍暂停。
