# MT6990 短信转发

## 使用方式

入口为“蜂窝 → 短信转发”，默认关闭。填写目标后，可同时启用：

- Webhook：通用 JSON，以及企业微信、钉钉、Telegram、Bark、PushPlus 模板。
- 邮件：SMTP TLS / STARTTLS，支持用户名和授权码。
- 手机短信：通过本机 SIM 和原厂 RIL 接口发送到一个目标号码。

模板填入后需替换自己的密钥、机器人 Token 或 Chat ID。Webhook 中的
{from}、{text}、{time}、{device} 在 JSON 解析之后替换，短信中的引号、换行
不会成为 JSON 语法或 shell 命令。钉钉当前支持不启用加签的机器人接口，
未实现钉钉动态签名。自建 Webhook 可使用 HTTP 或 HTTPS；TLS 校验不关闭，
不跟随重定向，不允许切换为 file 等协议。

保存并应用后，可点击“发送测试”，下一次采集周期向所有启用的渠道投递合成测试。
测试不经过关键词过滤，不会把收件箱历史短信作为测试内容。默认周期 60 秒，
可设置 30–600 秒；保存配置后首次成功扫描只建立已有完整短信的基线。
SIM 切换后同样先建立基线；普通重启保留同一基线与去重记录。

支持逗号分隔的发件号码黑名单和一个包含关键词条件。每种渠道单独保存结果。
手机短信不转发回原发件号码，中文和长内容按 UTF-16 单元拆分为独立短信，
保留分段序号，不在代理代码中冒充运营商拼接短信；每条原短信最多 20 段。
该渠道会使用 SIM 的短信套餐或产生运营商费用。

## MT6990 接口与所有权

没有安装展锐后台，也没有新增 UART/URC 读取者。

- 收件箱通过 lg6851f-sms-list → 既有 modem5g-at → atcid。
- 设置 CMGF=1、CSCS=UCS2 后执行一次 CMGL="ALL"，保留既有列表语义；
  CMGL 可能将未读短信标成已读，收件箱和转发共用这一读取路径。
- 原生 AT 客户端响应上限由 16 KiB 扩至 128 KiB，超限、缺少最终 OK、
  非 UCS2 或不支持的记录格式都报错，不用不完整列表建立基线。
- 接收列表和发送共用 lg6851f-sms-operation.lock，AT 请求仍使用原有 AT 锁；
  每次忙或临时故障让出通道，下个周期继续，不重启模组或改变射频策略。
- 发送继续使用 ql_sms_init / ql_sms_send_msg / ql_sms_release。
  qlril API 已确认提交后，释放失败不再让上层把该消息当成未发而重发。

### 中文发送的厂商二进制依据

以本仓库原有文件为依据，不套用 EC20、EC200U 等其他 SDK 的枚举：

- ql_ril_service SHA256：14ccd78c1396dcfd664d32d63eb9d5d1727e9bcfcfb48aa0586b2607f798eab1。
- libqlril.so SHA256：a5175cd120f938e9ebd22ffd2194e8ac28cd24e22c349250997116a21b776c20。
- libqlril.so 的 ql_sms_send_msg 位于 0x14f64，确认 1704 字节结构、
  format 位于 0，号码位于 4，content_length 位于 260，content 位于 264。
- ql_ril_service 在 0x41c2b8 比较 format=2 后跳到 0x41c5b8，
  在 0x41c5c4 引用 UCS2；该路径接收十六进制字符串并直接组装 AT+EMGS。
  format=1 会先把二进制内容转成十六进制，是另一条路径。
- 客户端 --ucs2 NUMBER UTF16BE_HEX 因此使用 format=2，长度填写十六进制
  字符串长度，而不是解码后的字节数；每段限制 140 字节的短信用户数据。

这些证明了封装和路由方式；接收与真实终端显示仍属于刷机后的实机验收。

## 可靠投递与保存位置

配置保存于 /etc/config/lg6851f_sms_forward，权限 600。
去重记录为 /etc/lg6851f-sms-forward/state.json，目录权限 700、文件权限 600。
记录使用 SIM 身份及消息来源、时间、正文的 SHA256 标识，不保存短信正文和密码。
写入采用同目录原子替换；外部投递之前先记录并同步 inflight，再保存最终结果。

- Webhook 先判断 HTTP 状态，预设渠道还检查服务 JSON 成功字段，避免把 HTTP 200
  的错误消息显示成成功。通用 Webhook 以 HTTP 2xx 为接收端契约。
- 发送幂等键和稳定邮件 Message-ID。第三方是否去重取决于其实现，不能承诺分布式
  投递绝对只发生一次。
- DNS/连接失败、HTTP 429/5xx、短信发送接口忙按退避策略自动尝试，最多 5 次。
- 超时、已发送后断开以及进程被中断的 inflight 记为“结果未确认”，不自动重发。
  人工核对后可点击“重试失败投递”，仅重试未成功的渠道或分段。
- 一个手机分段未确认后，停止其后分段。邮件或 Webhook 的失败不阻断其他渠道。
- 去重记录超过 2048 条时，先移除已不在当前收件箱中的旧记录；当前收件箱记录
  保留，异常超过 4096 条时停止并报告，不无限写满持久存储。
- 不自动删除 SIM 短信。待重试消息从收件箱重新读取，手动删除后不能恢复其正文；
  需要定期留意 SIM 收件箱容量。

状态缓存和本次投递临时文件放在 tmpfs 的 /tmp；临时目录为私有目录，
完成一轮后清理已创建的文件。正常重启清空缓存，后台重新生成状态。
状态 RPC 不含目标地址、账号密码或短信正文；编辑配置需要 LuCI 写权限，
SMTP 密码不回显，留空保留原值，可显式清除。

选择保留配置升级时，keep.d 同时保留转发配置和去重账本。
不保留配置升级时仍遵守此前的全新软件层策略，转发默认关闭，不迁移旧凭据。

## 编译与验证

固件配置和包依赖增加 curl SMTP/SMTPS 支持、CA 证书与 SHA256 工具。
Cloud Build 在 defconfig 后检查这些选择，最终根文件系统检查服务、页面、权限和工具。
保留原有编译、签名、A/B 包装及中文发布说明流程，源码仍只修改 cloud-build。

离线验证执行真实 ucode 解释器、真实文件系统和本机编译的 C 发送客户端，
仅替换外部模组及投递端：覆盖 Unicode、分片、去重、私密状态、错误成功响应、
多渠道隔离、重试与中断恢复。手机和桌面浏览器验证页面及保存配置路径。
离线通过不代表已在路由器上完成真实邮件、推送和运营商短信投递测试。
