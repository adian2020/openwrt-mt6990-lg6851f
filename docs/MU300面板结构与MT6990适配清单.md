# MU300 面板结构与 MT6990 适配清单

核对仓库：adian2020/mu300-linux，minikano-openwrt-feats 分支。
源码提交：1ba12fd4b8f830354a9c65fb3ac2f51222a0a28b。
路径：openwrt/luci-app-mu300。
菜单真源：root/usr/share/luci/menu.d/luci-app-mu300.json。

该插件是独立状态看板加蜂窝分组的一整套页面，并非 Aurora 主题本身。
Aurora 负责外观；luci-app-mu300 负责页面、业务接口、状态采集和控制逻辑。
下表记录上游页面范围；文末区分本次已接入内容与待验证项目。离线检查不代表
LG6851F 实机验收，当前仍暂停云编译。

## 共享层与后端依赖

- htdocs/luci-static/resources/mu300/common.js 是共享 RPC、格式化、多 SIM
  查看对象和主题样式层。它声明了 mu300status、mu300rates、mu300.modem、
  mu300dash 等对象，不等同于我们现有的 luci.modem5g。
- root/usr/share/ucode/mu300/dash.uc、rates.uc，以及 root/usr/libexec/rpcd/
  下的适配器提供业务后端。不能只复制页面或换主题就期待有真实数据。
- CPU、NFC、漫游、USB、充电、SIM 控制等分别有组件和后台。与硬件有关的
  操作保留禁用，直到平台能力、命令语义和实际读回验证完成。
- 状态看板包含快慢轮询与速率采样。移植时需要保留单一采集器，避免多个
  页面同时打开排他的 MIPC/AT 控制通道。

## 用户实机报告对适配的约束

用户提供的是 r0-07a0dbe 的运行数据，不是未完成的新 Aurora 固件。
这里只记录字段可用性，不把用户原始报告、设备身份或客户端地址提交到仓库。

- 实际蜂窝接口由 ubus 返回，不写死。APN、IPv4、DNS、接口时长均有值。
- NR 原始 CESQ 可以与现有 RSRP/RSRQ/SINR 结果交叉核验；RSSI 未提供时不能填 0。
- 现有 RAT 缓存只标识 5G，不能据此断言 SA/NSA。
- 已出现 soc_max、cpu_little0..3、gpu*、infra、connsys、md0..3 温度节点。
  页面应标注真实传感器，不能把所有 md 温度直接命名为外置模组温度。
- 两个 MT7996 hwmon 名称与无线接口后缀不直接一一对应，需要确定映射；
  一个固定低温读数不能直接认定为当前运行的 5GHz Wi-Fi 温度。
- cpufreq/policy* 采集为空。CPU 当前/最高频率仍为未获取。
- Linux conntrack 有真实总数和上限，但不能冒充 PPE0/PPE1 硬件绑定数。
- 网络仅返回 fe80:: 链路本地 IPv6 及同类前缀，不能显示为公网 IPv6 正常。
- 无线信道、带宽、发射功率、关联速率、客户端信号、DHCP 租约已有可读值。

## 第一阶段适配进度

- 新增独立 MT6990 状态看板，使用现有蜂窝缓存、实际数据接口、sysfs/procfs、
  netifd/iwinfo 和 DHCP 租约。温度保留原始传感器名；当前内核没有的频率显示未获取。
- 快速轮询只读接口字节计数和 CPU 时钟计数，按差值计算速率与 CPU 利用率；
  启动标识、接口变化或计数器归零时重新建立基线，不制造负速率。
- 新增 APN 页面，复用 network.modem5g/ql_datacall；仅保存和保存并应用分离，
  不创建第二个蜂窝接口。密码不回传，留空保留，另设明确清除选项。
- 保留原有短信、AT、网络锁定和拨号后端；SIM、CPU、设备、TTL 和适配设置
  先接入可确认的只读字段。SIM 标识默认遮罩，完整号码仅在主动点击后显示。
- 流量页面目前仅显示内核接口累计；跨重启历史、套餐周期及额度尚未实现。
  短信转发没有可用事件池，尚未接入，页面不能启动转发。电池菜单保持隐藏。
- ucode 数值使用浮点运算，避免整数除法截断温度、内存比例及 CPU 百分比；
  使用原生解释器验证字段缺失、计数器重置、密码保护及 APN 应用边界。
- 页面经过 Aurora 样式下的 390px/1280px 离线浏览器检查；真实设备的显示、
  APN 保存应用与长期轮询仍需验证。
