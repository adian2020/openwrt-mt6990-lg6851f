# MU300 短信与短信转发移植

## 对照来源与范围

按用户要求，对照 `adian2020/mu300-linux` 的 `minikano-openwrt-feats` 分支，固定提交 `b35932ab3c7c7f1df3e1ad6a74056835bef13867`，移植 `openwrt/luci-app-mu300/htdocs/luci-static/resources/view/mu300/{sms.js,forward.js,sms.css}`。许可证及来源随包保留。

短信页面沿用会话列表、未读数量、聊天气泡、收件人输入、Enter 发送/Shift+Enter 换行、SIM 同步、本地清空、单条本地或本地加 SIM 删除。默认聚合最近50条，增加“加载更多”访问更早记录；页面切换注销轮询。源码菜单改用 `sms_v3`、`forward_v2`，共享适配层为 `modem5g/sms_mu_v1`，LuCI包 release24。

转发页面沿用双列卡片、Webhook/钉钉/SMTP/本机短信配置、JSON/Bark/PushPlus/ServerChan/Telegram/企业微信/钉钉预设、GET/POST、JSON/Form/纯文本正文、请求头、超时、成功响应条件、设备备注、号码与关键词黑名单、模板语言、保存确认、测试和最近30次投递记录。SMTP授权码和钉钉密钥不回显，留空保留，显式勾选才清除。

以下适配不是 MU300 硬件能力的复制，不能宣称两机所有功能已完全相同：

- LG6851F为单SIM，隐藏多卡配置和切换，使用本机接口。没有移入MU300的Unisoc/Android/双SIM控制或另建UART读进程。
- 没有经过验证的有效电池传感器，电源通知保留为不可用提示，不虚构充电、电量或通知能力。
- 保留原有Webhook、SMTP、短信三渠道同时启用；选择框用于编辑渠道，三个复选框分别启用。Webhook与加签钉钉共用一个网络推送渠道。另存 `webhook_kind`，编辑SMTP/短信时不改变已启用的钉钉传输。
- 保留旧配置的正向关键词过滤、独立SMTP发件地址和轮询间隔；原有配置与持久去重账本继续使用。
- 不自动删除SIM短信。先归档，只有用户明确选“本地 + SIM”才删除；纯本地删除留下持久标记，下次同步不重新出现。
- 官方SDK支持单段Unicode发送。长文本拆成带 `[序号/总数]` 的独立短信，最多20段，并非伪装成已验证的原生PDU长短信发送。发送前提示费用，未知结果不自动重发。

## 后端与持久化

新增 `lg6851f-sms-pool` procd服务，后台调用已有 `lg6851f-sms-list` 与 `modem5g-at`，沿用atcid和短信互斥锁；没有抢占模组设备节点。首次拨号期间让行，联网稳定30秒后同步；已稳定启动、数据拨号关闭但射频明确注册且缓存新鲜时也允许读取。遇到用户模组操作或恢复标记则让行。SIM容量按实际 `AT+CPMS?` 返回显示，不支持或失败时不造数；容量缓存在 `/tmp`，不会仅因轮询容量重复写闪存。

- 本地短信、已读、本地删除标记与发送预留：`/etc/lg6851f-sms/pool.json`，目录0700、文件0600，升级保留清单包含该目录。
- 快照、当前异步任务、采集状态：`/tmp/lg6851f-sms-*`，文件0600；任务限定本次启动。
- 转发配置：原 `/etc/config/lg6851f_sms_forward`；默认关闭。
- 转发持久账本：原 `/etc/lg6851f-sms-forward/state.json`；最近投递展示仅在 `/tmp`，清空展示不清去重。

本地池同目录临时文件原子替换；持久写入同步落盘。已有文件损坏时保留并报错，不静默初始化覆盖。最多4096条归档、8MiB文件和16384个本地删除标记；达到上限报告清理/备份需求。仅完整短信入库，分片合并后保留全部SIM索引。发送通过现有 `modem5g-sms-send` 官方qlril API，异步任务先预留，再逐段记录提交；中断或超时不自动重发。短信显示、列表刷新只读本地数据（取全文会标为本地已读），不在页面RPC执行慢模组采集。

“本地 + SIM”在短信操作锁内重新读取，核对SIM身份以及号码、时间、内容的指纹后才按当前索引删除；换卡、索引被其他内容复用、读取不完整时拒绝误删。没有批量无校验的 `AT+CMGD` 删除。

新增转发能力仍沿用既有持久预留及各渠道状态：首次开启/改配置只建立历史基线；连接失败保留原有最多5次有界重试，投递不确定仅人工确认后重试。不因网页刷新、清投递记录或进程重启补发已处理短信。多号码转发最多3个，跳过原发件人不阻止后续其他号码。密钥放在0600临时curl配置中，不放到命令行或投递状态；钉钉HMAC-SHA256调用原生ucode digest，不通过shell展开正文。
