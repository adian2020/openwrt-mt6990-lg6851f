# LK采集失败提示修复

用户运行58f18b0版LK只读采集脚本后直接返回提示符，没有完成信息及压缩包。该版把读取stderr写入identity.txt，并存在直接exit 95的设备身份/节点检查；set -e退出时没有统一终止提示。单凭终端输出不能区分节点缺失、身份不符、超时、读取失败或其他命令错误，具体原因仍待现有报告返回。

采集版本2增加统一EXIT处理：保留退出码、当前阶段和完整读取的LK数量到status.txt；异常也尝试打包已采集的身份与诊断文件。未通过长度核验的读取文件改名为.img.partial，明确标为不完整，不能当作完整LK镜像。超时、不存在设备、无LK、超限或早期失败均显示阶段和诊断位置，不以生成tar.gz冒充LK读取成功。

保存原始stdout/stderr到独立描述符，确保错误若发生在identity信息整体重定向内部，EXIT提示仍能回到终端。打包失败时打印原始目录；不能捕获SIGKILL、断电或内核崩溃，不保证这些情况下生成压缩包。现存旧采集目录不删除、不再次读取；先查看其中identity.txt定位实际原因。

原先LK名称/设备检查、8MiB单分区上限、12秒单次超时及只读操作保持，不新增写misc、切槽、重启、格式化或自动挂载。

5项目标采集夹具回归通过：LK完整采集且源文件不变；LK不存在/超限拒绝；设备节点缺失显示阶段并保存诊断；读取超时保留.partial并标注不完整；identity阶段失败仍在终端显示诊断包路径。shell/Python语法及diff检查通过。没有再次读取用户设备、触发云编译或修改手动选槽逻辑。
