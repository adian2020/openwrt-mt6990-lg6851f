# LG6851F 转发性能基线

先在当前固件保留同一组运行配置，把四条路径的双向吞吐和转发计数作为基线。原厂 A 槽采样得到蜂窝入口 450.7 Mbps，自编译固件停用旧 QoS 后的下载实测为 350～400 Mbps。两组数据使用不同采集口径，新的对照使用相同端点和测试参数。

## 测试端点

| 路径 | 客户端 | 服务端 | 核对条件 |
| --- | --- | --- | --- |
| 蜂窝 ↔ Wi-Fi | 通过 5 GHz 连接 LG6851F 的设备 | 自己控制的蜂窝 WAN 外部服务器 | 确认流量走蜂窝默认出口 |
| 蜂窝 ↔ 有线 | LG6851F 的有线 LAN 客户端 | 同一台外部服务器 | 使用有线连接及相同的蜂窝出口 |
| 有线 ↔ Wi-Fi | LG6851F 的 Wi-Fi 客户端 | LG6851F 的有线 LAN 客户端 | 在同一允许互访的 LAN 测量桥接转发 |
| 同 BSSID Wi-Fi ↔ Wi-Fi | 无线客户端 1 | 无线客户端 2 | 两台设备连接同一个 5 GHz BSSID，并允许按现有策略互访 |

服务端应在表中的另一端。把服务端放在路由器自身，只能测量到路由器的吞吐。通过实际连接信息确认频道、带宽和 BSSID，同名 SSID 可能来自不同频段或接入点。隔离、访客网络及 VLAN 保持原有策略。

两端都需要 `iperf3`。电脑可使用系统已有工具。实验分支会在成功编译后将 `iperf3` 和 `libiperf3` 放进本次签名 APK 库，固件不预装，也不会启动测速服务。需要在路由器使用命令时，从该固件自己的源执行 `apk update` 和 `apk add iperf3`。

## 测速

在测试端点启动服务端，将 `SERVER_IP` 设为这台端点可被客户端访问的地址。使用已允许客户端连接的测试端点。

```sh
iperf3 -s -B "$SERVER_IP" -p 5201
```

在客户端设置同一个 `SERVER_IP`，依次执行下列命令。WAN 路径中，第一条测上行，第二条测下行。

```sh
iperf3 -c "$SERVER_IP" -p 5201 -t 20 -O 3 -P 1
iperf3 -c "$SERVER_IP" -p 5201 -t 20 -O 3 -P 1 -R
```

每个方向测三次并记录接收端中位数、单次范围和发送端重传。需要测四连接时，额外跑一组 `-P 4` 并单独记录。IPv4 和 IPv6 可分别用 `-4` 和 `-6` 对照。测完关闭服务端。

## 记录对照条件

- 记录固件 SHA、槽位、客户端与端点、Wi-Fi 频率及协商速率、有线链路速率和蜂窝小区信息。固件间复测使用相同端点、位置和测速参数。
- 每轮记录实际 QoS 队列、IFB 和 DSCP 规则状态。v1.0.21 开机启用旧 QoS，历史高速样本是在手动停止后取得的。一次对照只改变一个待验证因素。
- 在同一次测速的开始与结束读取 `/proc/stat`、`/proc/net/softnet_stat` 和 `/proc/interrupts`，按增量比较每核负载、丢包和实际中断分布。同时记录该流量经过的每个接口的 RX/TX 字节及丢包计数。接口吞吐和 `iperf3` 接收端吞吐分别记录。
- 接入 WED/PPE 后，分别记录设备绑定及实际流方向的硬件计数增量。模块加载、某个 WED 中断增长和流卸载命中是不同证据。同 BSSID 路径还要核对重关联、隔离或 VLAN 阻止转发时的行为。
