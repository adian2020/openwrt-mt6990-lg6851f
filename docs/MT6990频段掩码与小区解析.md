# MT6990 频段掩码与小区解析

本次根据用户提供的 get_cells 和 lg6851f-modem-lock get 原始输出核对。
不将用户原始小区标识、设备身份或完整日志提交到仓库；测试使用合成位置标识。

## 频段掩码

厂商打印格式是低位在前的 32 位字序，每个字用 8 位十六进制显示；
不能把整个字符串视为高位在前的大整数。第 k 个字的第 j 位对应频段
32 × k + j + 1，k、j 从 0 开始。

模组支持：

- LTE：B1、B3、B5、B7、B8、B20、B28、B32、B38、B40、B41、B42、B43、B46。
- NR：n1、n3、n5、n7、n8、n20、n28、n38、n40、n41、n75、n76、n77、n78。

页面区分当前允许频段与模组支持能力，按两组回读分别解码。读取当前掩码不代表
当前载波聚合组合，也不能据此得出 SA/NSA。

### n76 的读取能力与手动设置能力不同

原始能力掩码包含 n76；固件所带 sample_nw 的 NR 输入校验未接受 76。
该程序是 vendor 原有的 aarch64 二进制，并未在此次修改中替换或打补丁。
核对版本的 SHA-256：
`571e4f0f969443fa21cd4d29beac3a3d6e5bbb8e6885a3b3d8361f31c6b1d22b`。
离线反汇编核对到 0x4068b0..0x4068c4：对 66..79 的输入用 0x3a31 检查，
允许 66、70、71、75、77、78、79，未包含 76；与其菜单缺少 n76 一致。

因此 n76 在能力列表中只读展示，不传入手动设置接口。n75 已补入现有回读
校验路径，实际选频尚未在用户设备执行。根据随后确认的整机标称规格，
B46 与模组原始能力分开：保留其回读信息，仅只读展示，不开放整机手动设置。

“恢复默认”调用原有厂商恢复 API，之后同时读取当前与支持掩码并比较，
不再用不完整的手写数组认定恢复结果。手动设置则比较掩码的全部位，
防止忽略额外启用的频段，包括 n76。

## ECELL 记录

已收到的格式为数量字段加每条 15 个 CSV 字段。本次样本包含一个服务小区
和四个邻区，均为 RAT 11；邻区的空 MCC/MNC 不应导致字段错位。

| 行内索引（从 0 开始） | 内容 | 当前解析 |
|---|---|---|
| 0 | RAT | 11 为本样本 NR；7 按现有 LTE 路径处理 |
| 5 | PCI | 保留 0；空值不转成 0 |
| 6 | RSRP 编码 | NR 减 156，单位 dBm |
| 7 | RSRQ 编码 | 除以 2 再减 43，单位 dB |
| 11 | SINR 编码 | 除以 2 再减 23，单位 dB |
| 14 | ARFCN | 整数频点编号 |

空值、255 和超出编码范围的信号值保持缺失；截断、字段数量不符和失败响应
不生成可点击的小区。LTE 的转换沿用现有路径，本次没有新增 LTE 实机样本。

ARFCN 只能提供候选频段。n77/n78、n7/n41 等存在范围重叠，不自动任选一个
写入锁定表单。候选不唯一时回填 PCI/ARFCN，并保留“请选择频段”。
邻区条数不是载波聚合数量；EINFO 返回 0 也不提供带宽、MCS 或 AMBR。

## 看板采样与后续验证

- 既有 get_cells/get_locks 成功读取时发布仅 root 可读的 /tmp 快照，包含
  boot_id 和采样时间；读取失败不会覆盖上一次成功结果。
- 状态看板自动刷新仅读取快照。用户主动刷新小区时才调用原有查询接口，
  不新增 AT/MIPC 后台轮询。超过 180 秒的样本显示过期，重启后的旧样本不复用。
- 新鲜小区样本存在时，看板信号与表格使用同一响应；不与另一时刻的 CESQ
  拼出一组混合信号。接口速率仍独立读取实际网络计数器。
- 已完成原生 ucode、shell 掩码验证与共享 JavaScript 解析测试，以及 Aurora
  样式下手机/桌面离线检查。上述验证不代表模组选频已在实机执行。
- 已收到厂商 21、25/5、33 项原始采样并接入已确认的带宽、主载波/MCS、AMBR
  和 EN-DC；仍未验证的枚举、QCI、实际 SA/NSA 不填入看板。详见
  [高级射频参数读取](MT6990高级射频参数读取.md)。
- 云编译继续暂停。
